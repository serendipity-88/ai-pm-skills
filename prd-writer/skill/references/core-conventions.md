# 写作基座规范

> 所有文档类型必须遵守的基础规范。
> 加载时机：Step 3（确定文档类型后立即加载）

---

## 1. 数据表达格式

| 场景 | 格式 | 正确示例 | 错误示例 |
|------|------|---------|---------|
| 变化趋势 | `X%→Y% (+Zpt)` | `80.84%→88% (+7.16pt)` | `从80.84%提升到88%` |
| 占比 | `X%` | `成功率94.89%` | `成功率约95%` |
| 量级 | `约X万/亿` | `约2.76亿量级` | `大量用户` |
| 公式 | `指标 = 分子 / 分母` | `挽回率 = 成功订单 / 曝光pv` | 文字描述口径 |

**注意：**
- 用 `pt`（point）表示百分点
- 用 `pp`（percentage point）表示万分点
- 近似值用 `～`：提升`～0.06pt`

---

## 2. 表达原则

### 2.1 口语化（避免）

第一人称主观表达影响专业性，应直接陈述数据或事实。

| 避免 | 替代 |
|------|------|
| 我觉得 | 直接陈述数据或事实 |
| 看起来 | 直接陈述观察结果 |
| 可能 | 用"待确认"标记或给出概率 |
| 应该 | 用"支持/需要/不做" |

### 2.2 空洞修饰（需有数据支撑）

空洞的程度词缺乏信息量，应在需要精确描述的场景提供具体数据。

| 场景 | 原则 | 示例 |
|------|------|------|
| 背景描述/通识介绍 | 可用 | `大量历史数据表明...` |
| 效果描述/结论陈述 | 必须有数据 | `转化率从72%→85%（+13pt）` |
| 趋势变化 | 必须有数据 | `成功率提升显著，+3pt` |

**判断标准**：读者看完后能否回答"具体是多少"？如果不能，则空洞。

### 2.3 情态词（按场景使用）

情态词本身不是问题，问题在于是否用对了场景。

| 场景 | 推荐 | 可用 | 慎用 |
|------|------|------|------|
| PRD/规格定义 | 支持、需要、不做 | 可以、可 | 确保 |
| 汇报/分析 | 可以、建议 | 支持、需要 | 确保 |
| 应急/安全场景 | 确保 | - | - |

**原则**：越接近执行层面（PRD），语气越确定；越接近分析层面（汇报），语气越中立。

## 3. 符号规范

| 符号 | 用途 | 示例 |
|------|------|------|
| `→` | 变化/流程/转化 | `15%→44.32%`、`入口→教育页→转化` |
| `「」` | UI元素、按钮文案 | `点击「确定」按钮` |
| `#{}` | 动态内容占位 | `最高可减 #{动态金额} 元` |
| `｜` | 标题领域分隔 | `支付成功率｜设备无网支付方案` |
| `~~` | 已放弃方案 | `~~涉及多端改造，成本较高~~` |
| `（）` | 可配置项/补充说明 | `（2s时间可配）` |

---

## 4. 颜色语义系统（跨类型统一）

| 色值 | 语义 | 使用场景 |
|------|------|----------|
| `#DF2A3F` | 关键/变化/待确认 | 本周新发生、关键数据、待确认事项 |
| `#ED740C` | 需关注/推进中 | 待推进、需协调、方案待评审 |
| `#E8F7CF` | 正向里程碑 | 重要正向里程碑达成（绿底） |
| `#2F4BDA` | 未来动作 | 下周计划、未来动作 |
| `#8A8F8D` | 非本期/次要 | 已稳定运行、暂推迟、非本期 |

**核心原则：**
- 只标增量，不标存量
- 只标变化，不标常态
- 数据值标红，指标名称不标红

---

## 5. 日期格式

| 场景 | 格式 | 示例 |
|------|------|------|
| 技术文档 | `0424` | `0424已上线` |
| 汇报文档 | `5月24号` | `4月24号已全量` |
| 禁用 | `4/24`、`5/24`、`4月24日` | - |

---

## 6. 通用术语（无需解释）

- NFC支付、WebView、H5
- AB实验、实验组/对照组
- UV/PV、转化率、留存率
- 埋点、曝光、灰度、全量
- 配置化、降级方案

---

## 7. 不确定性分级标记

| 确定性 | 标记方式 | 示例 |
|--------|---------|------|
| 已确定 | 直接陈述 | `支持组合支付` |
| 需确认 | 红色+待X | `<font color=#DF2A3F>待技术确认</font>` |
| 暂推迟 | 灰色文字 | `<font color=#8A8F8D>非本期</font>` |
| 已放弃 | ~~删除线~~ | `~~涉及多端改造~~` |

---

## 8. 检查清单（通用）

- [ ] 数据格式：效果描述是否有 `X%→Y% (+Zpt)`？
- [ ] 口语化：背景描述外的结论陈述是否避免了"我觉得/可能/看起来"？
- [ ] 空洞修饰：结论陈述是否提供了具体数据支撑？
- [ ] 情态词：PRD类文档是否使用了"支持/需要/不做"而非模糊语气？
- [ ] 日期格式：是否符合 `0424` 或 `5月24号` 规范？
- [ ] 颜色标注：是否只标增量/变化，存量不标？
- [ ] 符号使用：是否使用 `→/「」/#{}` 而非文字描述？
