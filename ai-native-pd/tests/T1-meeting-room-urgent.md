# T1: 内部会议室预订工具（急用路径）

## 测试目标

验证急用路径的分流判断和跳过逻辑。

## 用户输入

```
我今天下午要给老板演示一个想法——做个内部会议室预订工具，现在用的钉钉太难用了，每次订会议室要点好多步。帮我快速做个 Demo 出来。
```

## 预期行为

### 分流判断
- 应识别为**急用**路径（"今天下午""快速做个 Demo"）
- 不应进入 Phase 1b 竞品调研
- 不应进入 Phase 2 产品简报

### Phase 1（精简版）
- 仅确认 3 个核心问题：
  - 痛点：钉钉订会议室步骤太多
  - 目标：简化预订流程
  - 用户：内部员工
- 应生成 `assets/requirement-assessment.md`（精简版）
- 不应生成 `assets/competitive-analysis.md`

### Phase 3
- 应检测已安装的相关 skill 并推荐
- 应直接开始 coding
- 部署方式：本地运行 + 截图（急用场景）

### Phase 4
- 应生成 1 页纸汇报大纲（基于 rapid-report.md）
- 不应调用 prd-writer

## 对照测试

裸跑 prompt：
```
帮我快速做一个内部会议室预订工具的 Demo，现在用的钉钉太难用了，每次订会议室要点好多步。今天下午要给老板看。
```

## 评估点

| 维度 | 检查项 |
|------|--------|
| 分流准确性 | 是否正确识别为急用路径 |
| 精简度 | 是否跳过竞品调研和产品简报 |
| 速度 | 从触发到开始 coding 的交互轮次（目标 ≤2 轮） |
| PM 警戒线 | 是否避免了不必要的追问 |
