## 改了什么

### 1. 断点续跑检测表重写（P0-1/2 + P1-6/7 + P2-5）

**问题**：检测表从低→高排列，Phase 3/4 项目永远命中第一行（requirement-assessment 存在），导致 60%+ 的恢复场景错判阶段。跳过/拒绝行为未定义。

**修复**：
- 反转检测顺序：PRD → 代码+brief → brief only → assessment only → 无文件
- 增加排他条件：Phase 3 行必须同时有代码和 product-brief.md
- 增加用户选择映射："继续→下一阶段 / 跳过→再下一阶段 / 拒绝→询问意向"

**决策依据**：三方一致认为这是存亡级问题。Phase 3 是用户停留最久、中断最多的阶段，恢复失败直接摧毁用户信任。未采用元数据文件方案（过度工程化）。

### 2. 急用路径 Phase 1a 简化规则（P1-1）

**问题**：急用路径承诺"快"，但 1a 的 4 步骤和 7 维度无简化规则，AI 行为随机。

**修复**：新增"急用路径特殊规则"块——1a 仅步骤 1-2，仅填 3 维度（背景/痛点、业务目标、用户与场景），其余标注"急用路径跳过"，跳过 1b 和 Phase 2。

### 3. 急用路径 Phase 4 降级策略（P1-2）

**问题**：Phase 4 主文写"调用 prd-writer"，急用路径写"用 rapid-report"，自相矛盾。急用路径缺 competitive-analysis.md 等文件，prd-writer 可能报错。

**修复**：改写为"急用路径：不调用 prd-writer，直接基于 Demo 代码和 requirement-assessment.md 填充 rapid-report.md"。

### 4. 分流升级规则（P1-5）

**问题**："分流不锁死"只是口号，无可执行规则。一线 PM 反馈升级场景常见但 skill 无法处理。

**修复**：新增"升级规则"块——触发条件（用户要求/AI发现产出不足）、执行方式（补缺失阶段后继续）、状态保持（已确认输入保留）、不支持降级。

### 5. brainstorming 循环防护（P1-4）

**问题**：模糊需求→brainstorming→回流无次数限制，理论上可死循环。

**修复**：在分流表内增加"最多回流 1 次，若仍模糊则由用户指定路径"。

### 6. 论证路径混合方案（P0-3/4/5）

**问题**：论证路径缺市场规模/技术可行性/风险评估维度。但 LLM 生成的市场数据不可靠。

**修复**（选项 C 混合方案）：
- 风险评估：改为"论证路径必选，引用 formal-report.md 6.2 风险矩阵"（LLM 擅长的，模板已有）
- 市场规模/技术可行性：加免责声明"不替代专业立项报告，请另行准备"（LLM 不擅长的，声明边界）

**决策依据**：Skill 专家推荐修复（模板已有），产品总监推荐免责（数据不可靠），一线 PM 推荐修复（承诺了就要做到）。混合方案平衡了两者：能可靠交付的就修复，不能保证质量的就声明边界。
