## 二、问题详情

### 问题 1：交互描述缺少异常/降级场景

**检查项**：每个可交互元素是否覆盖默认状态、触发、行为、取消、降级

**问题描述**：根据维度推断 `#20 交互规范: 复合交互`，PRD 需要为每个可交互元素覆盖 5 项内容。当前"模块二：预订确认浮层"的交互规范缺少异常/降级场景描述。

**已覆盖**：
- 默认状态：✅ "默认居中展示，带半透明蒙层"
- 触发动作：✅ "点击确认按钮"
- 行为结果：✅ "浮层关闭，格子切换为已预订状态，显示成功提示"
- 取消/关闭：✅ "点击蒙层/取消按钮，关闭浮层，格子恢复空闲状态"

**缺失**：
- 异常/降级：❌ 未描述预订失败场景

**修改建议**：在"模块二：预订确认浮层"的交互规范中补充：

```markdown
**交互规范**

* 浮层默认居中展示，带半透明蒙层
* 点击蒙层，关闭浮层，格子恢复空闲状态
* 点击「确认」后，浮层关闭，格子切换为已预订状态，显示成功提示
* 如预订失败（网络异常/接口超时/会议室已被占），显示错误提示，格子恢复空闲状态
```

### 问题 2：缺少配置化设计章节

**检查项**：配置化字段是否覆盖所有面向用户的文案和数据

**问题描述**：PRD 中提到了配置化项"2s 后自动消失（时间可配）"，但未系统列出所有配置化字段及其配置入口。

**当前提及的配置化项**：
- 成功提示消失时间："2s 后自动消失（时间可配）"

**缺失项**：
- 配置入口说明（从哪里配置？）
- 时段视图时间范围是否可配
- 按钮文案是否可配

**修改建议**：新增"五、配置化设计"章节（调整后续章节编号）：

```markdown
## 五、配置化设计

| 配置项 | 默认值 | 配置入口 | 说明 |
|--------|--------|----------|------|
| 成功提示持续时间 | 2s | 服务端下发 | 预订成功后提示自动消失时间 |
| 时段起始时间 | 08:00 | 服务端下发 | 时段视图显示的起始时间 |
| 时段结束时间 | 24:00 | 服务端下发 | 时段视图显示的结束时间 |
| 会议室数量 | 5 | 服务端下发 | 时段视图展示的会议室数量 |
```
