# 测试用例：图片占位符生成逻辑

## 测试目标

验证 prd-writer skill 在生成 PRD 时，能否正确识别需要图片占位符的场景，并按格式生成占位符。

## 测试材料

| 文件 | 说明 |
|------|------|
| `demo.html` | 会议室预订 Demo（单页面 H5） |
| `product-brief.md` | 产品方案简述 |

## 预期推断结果

根据 `dimensions.yaml` 应推断出：

| 维度 | 预期结果 | 触发图片类型 |
|------|---------|-------------|
| #1 产品类型 | H5 页面 | Demo 页面截图 |
| #2 产品规模 | 单页面→轻量 | - |
| #3 复杂度 | 轻量（2 个功能模块） | - |
| #17 用户动线 | 单入口→不需要动线图 | - |
| #23 埋点追踪 | 需要（有数据指标） | 数据报表截图 |
| 多状态变体 | 有（空闲/选中/已预订） | 多状态对比图 |

## 预期占位符

PRD 中应包含以下占位符：

1. **Demo 页面截图** - 主界面时段视图
   - 位置：`demo.html` 主界面
   - 操作：需截图

2. **多状态对比图** - 会议室格子三状态对比
   - 位置：`demo.html` 中 `.time-slot` 的 free/selected/booked 状态
   - 操作：需截图后拼接

3. **Demo 页面截图** - 预订确认浮层
   - 位置：`demo.html` 中 `#booking-modal`
   - 操作：需截图

4. **数据报表截图** - 埋点指标定义
   - 位置：待标注数据来源
   - 操作：需标注来源

## 验证步骤

1. 在 `tests/test-image-placeholder` 目录下运行 prd-writer
2. 检查生成的 PRD 中是否包含上述 4 个占位符
3. 验证占位符格式是否正确：
   ```
   > 📷 **图片占位**：{类型} - {说明}
   >
   > - 位置：{路径或来源说明}
   > - 操作：{手动上传/需截图/需导出/需自制}
   ```

## 通过标准

- [ ] 4 个预期占位符全部生成
- [ ] 占位符格式符合规范
- [ ] 没有多余的占位符（如流程图、状态机图等可自动生成的图表不应有占位符）
- [ ] 可自动生成的图表（如有）已生成 Mermaid/PlantUML 代码
