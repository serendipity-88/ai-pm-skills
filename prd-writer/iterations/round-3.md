# Round 3: 辩论驱动的改进 + 产出物持久化

**日期**: 2026-04-15

## 改了什么

### 1. 维度持久化
Phase 1 推断结果写入 `prd/.prd-cache/v{版本号}/dimensions.yaml`，Phase 3/4/5 从文件读取，不依赖对话上下文。

### 2. 轻量模式
Phase 1 推断后自动判断流程模式。轻量条件：#2=轻量 且 #3=轻量 且 #29≠多端 且 #25≠需要。轻量模式跳过 Phase 2 Round 1（成功指标讨论）和 Phase 3（框架确认），Phase 5 仅检查禁用表达和格式。

### 3. Phase 5 检查清单条件化
14 条拆为 5 条始终检查 + 9 条条件检查，subagent 传入 dimensions.yaml 根据维度结果跳过不适用的条目。

### 4. 隐藏模式标签
Phase 3 对用户展示自然语言（"页面结构描述"）而非内部标签（"模式 A"）。内部仍用 A/B/C/D 索引 style guide。

### 5. 适用场景声明
定位从"项目开发完成后"改为"已有原型、Demo 或方案文档后"。加 blockquote 说明前提：无材料建议走 ai-native-pd。

### 6. 产出物持久化
所有 Phase 产出写入 `prd/.prd-cache/v{版本号}/`：
- `dimensions.yaml` — Phase 1 维度推断
- `phase1-summary.md` — 项目理解摘要
- `phase2-decisions.md` — 成功指标 + 必问项回答
- `phase3-framework.md` — PRD 框架
- `phase5-review.md` — 质量检查报告

最终 PRD 输出到 `prd/PRD_v1.0.md`。迭代新建版本目录，不覆盖。

## 为什么改

基于两轮 subagent 辩论（3 视角锐评 + 答辩），识别出的核心问题：
- 长材料场景维度推断可能被挤出上下文 → 持久化
- 简单项目走完整流程太重 → 轻量模式
- Phase 5 对简单 PRD 检查太多无意义项 → 条件化
- 用户不理解内部术语 → 隐藏标签
- 定位"项目开发完成后"容易误解为上线后补文档 → 重写定位
- 中间过程产出只在对话里，关了就没了 → 全部持久化到文件

## 确认不做的

经两轮辩论后确认为伪问题。Phase 3/5 的 Claude 同时读 dimensions.yaml 和模板条件，做的是语义理解不是字符串匹配。真正的风险是推断本身出错，枚举化解决不了，Phase 5 subagent 兜底。

### 改进 7: 语雀配置默认值
目前只有用户自己在用，暂不改。
