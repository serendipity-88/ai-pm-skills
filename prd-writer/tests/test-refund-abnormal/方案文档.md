# 碰一下支付异常退款方案

## 背景

碰一下支付场景中，由于网络异常、设备故障等原因，可能出现支付成功但用户未收到商品的情况。需要提供异常订单的退款入口。

## 目标

- 异常退款成功率：95%
- 用户满意度：4.5分

## 产品方案

### 1. 异常退款入口

**入口位置**：支付记录页 - 订单详情页

**触发条件**：
- 支付成功超过 24 小时未收到商品
- 用户主动发起退款申请
- 系统检测到异常自动触发

### 2. 退款流程

**正常链路**：
1. 用户进入订单详情页
2. 点击「申请退款」
3. 选择退款原因（商品未收到、商品损坏、其他）
4. 提交退款申请
5. 系统审核（自动 + 人工）
6. 退款原路返回

**异常链路1 - 退款审核拒绝**
- 商家拒绝退款
- 用户可申诉或取消申请

**异常链路2 - 部分退款**
- 仅支持部分退款（如部分商品已发货）
- 用户确认后执行部分退款

**异常链路3 - 退款超时**
- 商家 48 小时未处理
- 自动触发平台介入

### 3. 状态机

```
已支付 → 退款申请中 → 退款审核中 → 退款成功
                    ↓
                退款审核拒绝 → 用户申诉 / 取消申请
```

### 4. 配置化

- 退款开关：商家可配置是否允许退款
- 退款时效：订单完成后 N 小时内可申请（默认 24h）
- 退款原因：商家可配置可选原因

### 5. 资金安全

- 退款需原路返回
- 大额退款（>500元）需人工审核
- 记录退款日志，支持审计

## 数据指标

- 北极星指标：异常退款成功率 = 退款成功笔数 / 退款申请笔数
- 退款申请率 = 退款申请 uv / 支付成功 uv
- 退款审核平均时长
- 用户退款满意度

## AB 实验

- 实验组 A：申请入口前置（订单详情页顶部）
- 实验组 B：申请入口后置（订单详情页底部）
- 对照组：当前入口位置

实验周期：7 天
核心观测：退款申请率、用户满意度
