# Round 2: 产出结构重构——从四文件到单文档+消费场景交付

**日期**: 2026-05-04
**类型**: 产出体验优化

## 改动

### 问题

Round 1 验证（线下商户私域运营）产出 4 个 MD 文件（competitive-analysis.md + 01-landscape.md + 02-deep-analysis.md + 03-decision-brief.md），阅读体验差：
- PM 拿到研究结果的第一反应不是"打开 4 个文件分别读"
- 三层分层按"信息密度"组织，但 PM 实际消费研究的方式是按场景：自己决策 / 向上汇报 / 团队讨论 / 存档备查
- 三层和四种场景不是一一对应的

### 核心设计变化

1. **生产侧：四文件 → 单文档**
   - 三阶段研究产出一份完整的 `research-report.md`
   - 文档内用明确的章节标记三个分层（第一层：决策简报 / 第二层：决策推理 / 第三层：研究数据）
   - 新模板 `templates/research-report.md` 替代原来的 4 个独立模板

2. **交付侧：按消费场景裁剪**
   - Phase 3 完成后询问用户的消费场景：
     - **快速决策**：只拿第一层（1-2 页决策简报）
     - **向上汇报**：第一层 + 第二层（决策简报 + 决策推理 + 风险）
     - **团队讨论**：第一层 + 第二层 + 第三层关键数据
     - **完整存档**：全部内容
   - 格式可选：Markdown / HTML 交互报告（可折叠章节）
   - 从完整文档提取对应内容，按选定格式输出

3. **被调用时：不询问消费场景**
   - 其他 skill 调用 pd-deep-research 时，直接产出完整 `research-report.md`
   - 调用方自行决定读取哪些章节

4. **消费场景选择时机：Phase 3 完成后（选 A）**
   - PM 在研究开始前往往不知道自己需要什么深度
   - 研究完了才知道"这个需要汇报给老板"或"这个自己决策就行"

### 旧案例文件处理

`cases/线下商户私域运营/` 中的 4 个文件（Round 1 验证产出）保留为旧格式参考，后续迭代中将迁移为单文档格式。

## 原因

1. 用户反馈：4 个 MD 文件阅读体验差，不符合 PM 消费研究的实际场景
2. 按信息密度组织 ≠ 按消费场景组织——PM 不是按"我要看高密度信息"来读报告，而是按"我要做决策/汇报/讨论/存档"
3. 生产结构和交付结构应该分离——生产时完整产出不丢信息，交付时按需裁剪不过载
4. 消费场景选择放在 Phase 3 完成后（而非研究开始前），因为 PM 研究前往往不知道需要什么深度

## 用户反馈

- "生产过程中，一可以作为最完整的产出结果，但应该从四的角度让用户来决策需要什么样的内容"
- "至于二（HTML），也可以加入到用户的选择中，在确定了消费场景后，可以选择产出形态"
- 消费场景选择时机选 A（Phase 3 完成后问），因为"PM 在研究开始前往往不知道自己需要什么深度"
