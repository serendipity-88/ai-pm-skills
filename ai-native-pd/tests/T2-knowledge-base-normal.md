# T2: 团队知识库搜索工具（正常路径）

## 测试目标

验证正常路径的完整 Phase 1-4 流程衔接，重点测试 Phase 1 发现 + Phase 2 定义。

## 用户输入

```
我们团队有很多文档散落在语雀、飞书、Confluence 各处，每次找个东西要翻好几个平台，特别浪费时间。我想做一个统一的知识库搜索工具，能一个入口搜到所有平台的内容。
```

## 预期行为

### 分流判断
- 应识别为**正常**路径（有明确想法，无时间压力）
- 应走完整 Phase 1 → 2 → 3 → 4 流程

### Phase 1a 问题定义
- **JTBD 转化**：应自动将用户描述转化为 JTBD 句式，例如：
  - "当团队成员需要查找某个文档时，想要在一个入口搜索所有平台，以便不用逐个平台翻找、节省时间"
- **需求分类**：应标注为**痛点**（现有方案有明确不满——"要翻好几个平台""特别浪费时间"）
- **7 维度评估**：
  - 能推断的维度应自动填充（痛点、用户、场景、现有方案）
  - 仅追问真正缺失的信息（如：团队规模、各平台数据量、是否需要权限控制）
- 应生成 `assets/requirement-assessment.md`

### Phase 1b 竞品调研
- 应**自动执行** web search，不需要用户额外输入
- 应搜索到相关竞品（如 Glean、Guru、Elastic Workplace Search、Algolia 等）
- 每个竞品应有结构化对比：怎么解决同样问题、核心差异、迁移成本
- 关键事实（定价、上线时间）应标注"待用户校验"
- 应生成 `assets/research-findings.md`

### Phase 1c 调研摘要
- 应一次性呈现：JTBD、需求类型、竞品现状、风险提示
- 应以"你觉得这个方向值得继续推进吗？"结尾
- **HARD-GATE**：应等待用户确认后才进入 Phase 2

### Phase 2
- 应从所有场景中裁剪出最多 3 个核心场景
- 应明确"做什么"和"不做什么"
- 应生成 `assets/product-brief.md`
- **HARD-GATE**：应展示产品简报摘要，等待用户确认

### Phase 3
- 应检测已安装的相关 skill 并推荐
- 应基于产品简报开始 coding
- Iterate 微循环：改 → 验 → 决

### Phase 4
- 应调用 prd-writer skill
- 应确保 Phase 1-3 产出文件在项目目录下

## 对照测试

裸跑 prompt：
```
我们团队有很多文档散落在语雀、飞书、Confluence 各处，每次找个东西要翻好几个平台。帮我做一个统一的知识库搜索工具，一个入口搜到所有平台的内容。
```

## 评估点

| 维度 | 检查项 |
|------|--------|
| JTBD 转化 | 是否从"做个搜索工具"还原到用户场景和动机 |
| 自动推断 | 7 维度中能推断的是否自动填充，追问是否精准（≤3 个问题） |
| 竞品搜索 | 是否自动执行、竞品是否相关、信息是否标注可信度 |
| 调研摘要 | 是否结构化呈现、风险提示是否有价值 |
| HARD-GATE | Phase 1→2、Phase 2→3 是否有确认门禁 |
| 场景裁剪 | Phase 2 是否收敛到 ≤3 个核心场景 |
| 范围边界 | 是否明确"不做什么"（如：不做内容编辑、不做权限管理） |
| 流程完整性 | 是否走完 Phase 1→2→3→4 |
