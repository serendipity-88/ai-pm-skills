# PD Deep Research

> 研究发现的价值在于它改变了什么产品决策，不在于它收集了多少信息。

## 定位

帮助 PM 完成早期需求阶段的信息收集和分析，最终产出的是**决策依据**，不是研究报告。调研产出的每个发现都应指向下游产品决策：做不做（方向判断）、做什么（产品定位与 MVP 边界）、怎么赢（差异化与竞争策略）、怎么赚（商业模式与增长路径）、怎么避坑（关键风险与应对）。

推荐使用场景：新赛道探索、竞品深度分析、技术选型论证、市场进入策略、产品创新方向研究，以及需要把信息整理成产品决策依据的早期研究任务。

## 独立运行与可调用

本 skill 完全独立运行，不依赖也不引用任何其他 skill。

- **独立运行**：用户直接触发时，完整执行三阶段，产出完整研究文档，再按消费场景交付
- **可被调用**：其他 skill 可传入研究主题 + 输出目录，本 skill 产出标准化文件，调用方自行读取
- **产出格式通用**：所有产出文件使用通用命名和格式，不针对任何特定调用方

### 被调用接口

当其他 skill 调用本 skill 时：

**输入**：
- `topic`（必填）：研究主题
- `output_dir`（必填）：输出目录路径
- `type`（可选）：产品/公司/技术/市场/人物
- `goal`（可选）：要解决什么决策问题
- `focus`（可选）：特别关注的方向
- `context`（可选）：调用方已收集的产品背景、用户核心任务、需求评估摘要、已知约束、特别关注点。被 ai-native-pd 调用时，应传入 Phase 1a 的结构化结果，避免研究退化成泛泛市场分析

**输出**：
- `{output_dir}/research-report.md` — 完整三层研究文档（始终产出）
- 不询问消费场景，不产出 HTML

**调用方读取**：
- 第一层（决策简报）：文档开头的 `# 第一层：决策简报` 到 `---` 分割线
- 第二层（决策推理）：`# 第二层：决策推理` 到下一 `---` 分割线
- 第三层（研究数据）：`# 第三层：研究数据` 到文档末尾

## 触发条件

| 用户意图 | 判断依据 | 路径 |
|---------|---------|------|
| **探索新方向** | "分析一下X方向""研究一下X""X领域怎么样" | 完整三阶段 |
| **竞品调研** | "看看竞品""分析一下XX""竞品怎么做" | 完整三阶段，竞争态势侧重 |
| **技术选型** | "X技术可行吗""X方案怎么选" | 完整三阶段，行业演变侧重 |
| **快速了解** | "帮我了解一下XX""XX是什么来头" | Phase 1 精简 + Phase 3 决策简报 |
| **简单比较** | "A和B比怎么样" | Phase 1 竞争态势聚焦 + Phase 3 决策简报 |
| **产品功能定位** | "这个功能怎么做""X产品该怎么定位" | 轻量模式（见下方） |

路径不锁死——过程中发现需要更深入分析时，可随时升级到完整三阶段。

### 研究范围评估

收到研究主题后，先判断范围大小，调整搜索策略：

| 范围 | 判断依据 | 搜索上限 | 竞品深度 | 产出规模 |
|------|---------|---------|---------|---------|
| 窄 | 单个功能/技术选型，竞品 ≤ 3 | 10 次 | 每个竞品深入 | 决策可少于 5 个 |
| 中 | 单个产品方向，竞品 3-10 | 15 次（默认） | 选 3-5 代表深入 | 完整产出 |
| 宽 | 整个市场/赛道，竞品 10+ | 建议拆分为 2-3 个窄/中研究 | 聚类为主 | 每个子研究完整产出 |

如果研究主题明显过宽（如"中国 SaaS 市场"），在 Phase 1 开始前建议用户收窄到具体产品方向。

### 轻量模式（产品功能定位 / 技术选型等窄问题）

当研究问题聚焦于一个已有产品/功能的方向选择时（而非市场机会判断），使用轻量模式：

**行业演变分析压缩**：不写完整的演变叙事，改为"关键路径依赖"段落（1-2 段，只讲与决策直接相关的历史锁定），省略"起源追溯"和"完整行业演变"

**竞争态势分析侧重调整**：
- 减少竞品聚类（窄问题通常竞品少，场景 A/B 更常见）
- 增加技术可行性验证和用户行为数据权重
- 竞品深度对比聚焦"与研究问题的差异点"而非全景扫描

**搜索策略调整**：
- 第一轮搜索减少到 2-3 次（窄问题不需要广度扫描）
- 增加定向搜索：技术文档、API 文档、用户反馈平台
- 总搜索上限降为 10 次

**产出调整**：
- Layer 3 行业演变压缩为"关键路径依赖"表格（替代完整叙事）
- Layer 3 竞品深度对比只展开与研究问题直接相关的维度
- 决策数量可少于 5 个（窄问题可能只有 2-3 个关键决策）

## Phase 1: 外面怎么样？

**PM 的问题**：这个领域格局是什么？怎么演变过来的？谁在做什么？

### 输入

- **研究主题**：具体的产品名/公司名/技术方向/市场领域
- **类型**（可选）：产品、公司、技术、市场、人物——影响行业演变/竞争态势侧重
- **研究目标**（可选）：要解决什么决策问题
- **特别关注点**（可选）：有没有特别想深入的方向

### 内部执行

**行业演变扫描**（历史演变）：
- 起源追溯：诞生的背景、驱动力、关键人物
- 行业演变：关键转折点、范式变化、什么驱动了变化
- 路径依赖：哪些早期决策锁定了后来方向

**竞争态势扫描**（现状竞争）：
- 竞品场景检测：
  - **场景 A**（无直接竞品）：分析为什么没有竞品、未来可能从哪冒出、间接替代方案
  - **场景 B**（1-2 个竞品）：逐一深入对比
  - **场景 C**（3+ 竞品）：按方案聚类，选 3-5 个代表深入分析
- 竞争格局图：按方案聚类而非按公司罗列
- **分析维度参考**（不需要全部覆盖，但至少覆盖 2-3 个维度）：技术架构、商业模式驱动、用户心智模型、设计哲学、增长策略、合规约束

**锚点评估**（内部元数据，不暴露给用户）：
- 每个信息源标注：优先级（高/中/低）、类型、可信度、时效性
- 按主题分组规划深度阅读批次

**信息源登记**（Phase 1 开始，贯穿全程）：
- 每个信息源分配编号（S1, S2, S3, ...），按首次出现顺序递增
- 记录：编号、来源名称、类型（原始来源/权威分析/二手分析/观点评论）、可信度（高/中）、访问时间、URL
- 正文中引用数据时标注来源编号，如 `Churnkey 2025[S3]`、`消保法条例[S1]`
- 信息源登记表在 Phase 3 组装时作为 Layer 3 末尾的"信息源"附录

**信息来源优先级**：一手来源 > 二手分析 > 观点评论。关键事实标注来源和访问时间。搜不到的信息标注"待验证"，绝不编造。

**搜索策略**：

搜索是 Phase 1 和 Phase 2 的核心执行动作，不是被动浏览。按以下规范执行：

*搜索轮次*：

| 轮次 | 目标 | 搜索次数 | 查询模式 |
|------|------|---------|---------|
| 第一轮 | 广度扫描 | 3-5 次 | "[领域] 发展历程/演变""[领域] 竞品/市场格局/[竞品名] 分析" |
| 第二轮 | 锚点精读 | 每次精读前 1-2 次定向搜索 | 竞品名+数据指标，补充证据缺口 |
| 第三轮 | 补缺验证 | 不超过 3 次 | 仅在信息充分性未通过时执行 |
| **上限** | — | **15 次** | 超过说明主题过大或查询策略有问题 |

*查询构造*：中文搜中文市场，英文搜全球/技术领域；具体优于抽象（"[竞品名] 付费商户数 2024" 优于 "SaaS 市场"）；数字锚定（带年份/数据指标）；矛盾搜索（发现矛盾时搜"XX 真实数据""XX 辟谣"验证）

*信息充分性判据*：

| 维度 | 通过标准 | 未通过 |
|------|---------|--------|
| 行业演变 | 3+ 关键转折点有因果解释 + 1+ 路径依赖有证据 | 执行第三轮 |
| 竞争态势 | 场景 C 至少 3 个聚类 + 每聚类 1+ 代表有数据 | 执行第三轮 |
| 来源 | 关键判断 2+ 独立来源 | 降为"待验证" |
| 矛盾 | 第三源验证或标注矛盾原因 | 不能静默选一 |

*薄结果回退*：
- 搜索结果 < 3 条有效信息：换查询词（更宽泛/同义词/英文），仍不足则标注"该方向信息不足"并调整研究范围
- 一手来源完全缺失：在产出中明确标注"本研究基于二手分析，缺乏一手验证"，将相关判断置信度上限设为"中"
- 竞品信息不对称（某些竞品信息丰富，某些极少）：标注信息不对称，对信息不足的竞品不做过深判断

*研究障碍处理*：

| 情况 | 处理方式 |
|------|---------|
| 主题信息极少（<5 条有效搜索结果，换词仍不足） | 在产出中标注"研究范围受限"，缩小研究方向到可搜索的子主题，产出聚焦结论 |
| 关键维度搜索结果全为二手分析 | 标注"本研究基于二手分析，缺乏一手验证"，关键判断置信度上限设为"中" |
| 初始假设被推翻 | 这是正常结果，Phase 2 的"被推翻"假设是有价值的发现，不需要重新开始 |
| 搜索结果均过时（>2年） | 标注信息时效性风险，在风险与待确认中增加"信息时效性风险"条目 |

### 产出

按产出写入规则，Phase 1 写入模板第三层的对应章节。具体产出：

- **行业演变**：因果叙事（不是年表），关键转折点表格
- **竞争格局**：竞争场景判断 + 方案聚类表格
- **初始假设**：需要 Phase 2 验证的假设列表

## Phase 2: 到底怎么回事？

**PM 的问题**：什么是真的？什么最重要？能信什么？

### 内部执行

**深度阅读**：按 Phase 1 批次规划精读高优先级锚点

**持续交叉验证**（嵌入本阶段，不是独立步骤）：
- 每个发现实时标注可信度：[高] 多源一致 / [中] 单源权威 / [待验证] 逻辑推断
- 识别多源一致模式
- 标记信息矛盾点及可能原因

**深层判断**：
- 过去的演变如何影响了今天的格局
- 当前优势/劣势的历史根源
- 趋势和现状交叉产生的机会
- **设计哲学与底层逻辑**：每个竞品/方案不仅要分析"做了什么"，更要分析"为什么这样做"——背后的设计哲学、平台基因、商业模型驱动。如："抖音的高频聚合算法源于其'极速海量'的内容引擎基因，小红书的保守聚合源于其'长效信任'的社区基因"
- **边缘陷阱与隐藏风险**：主动寻找"看起来正常但有隐藏风险"的架构决策、产品逻辑、商业模式（如：看似合理的默认行为在特定场景下产生数据泄露/用户流失/合规风险；路径依赖导致的架构死角）
- **新综合规则**：每条深层判断必须是 Layer 1 未出现的新判断，单独看趋势或现状都得不出。禁止把机会窗口的证据换个说法重排。引用 `references/writing-quality-standards.md` 中的"深层判断新综合规则"

**信息充分性自检**：
- 行业演变：至少 3 个关键转折点有因果解释？路径依赖有证据支撑？
- 竞争态势：竞品/方案聚类覆盖主要玩家？每个聚类代表有具体数据？
- 来源：关键判断至少 2 个独立来源？否则降为"待验证"
- 矛盾：发现矛盾信息时是否搜索了第三源或标注了矛盾原因？
- 未通过时：执行第三轮补缺搜索（不超过 3 次），仍不足则标注"信息不足"

### 写作要求

执行 `references/writing-quality-standards.md` 全部规则。核心自检：
- 每段通过 so-what 测试（删掉后是否影响决策？不影响就删）
- 每个 Phase 2 段落自检：判断 > 描述，因果 > 罗列
- 可信度标注一切（引用 `references/confidence-framework.md`）

### 产出

追加到 `research-report.md` 第三层"研究数据"章节（基于 `templates/research-report.md` 模板）：

- **验证发现**：高置信发现 + 中置信洞察，每个带可信度标签
- **深层判断**：趋势与现状交叉产生的新判断（必须满足"新综合"规则，见写作标准）
- **开放问题**：仍待验证的假设和需补充的信息
- **竞品深度对比**（如有竞品）：按方案聚类展开

**Phase 1→2 转换条件**（全部满足后进入 Phase 2）：
- 信息充分性判据至少 3/4 通过
- 至少 3 个初始假设已提出
- 搜索已达第一轮或第二轮
- 如果多个维度未通过，先执行第三轮补缺再进入

**Phase 2→3 转换条件**（全部满足后进入 Phase 3）：
- 初始假设全部映射到证据（已验证/部分验证/被推翻）
- 每个关键判断有可信度标注
- 信息矛盾点已标注或已解决
- 如有假设仍无证据，标注为"待验证"而非继续搜索

## Phase 3: 所以呢？我们该怎么做？

**PM 的问题**：有什么机会？该做什么？风险是什么？

### 内部执行

**假设验证**：将 Phase 1 的初始假设逐一映射到 Phase 2 的证据，标注：已验证 / 部分验证 / 被推翻

**机会识别**（结构化方法）：
- 趋势与现状的交叉机会：市场趋势指向但当前竞品未覆盖
- 用户痛点空白：竞品用户普遍抱怨但无人解决
- 时机窗口：技术/市场/监管变化打开的时间性机会
- 演进方向：当前方案正在向什么方向演进？下一代可能是什么样？这如何影响我们的技术选型和投资节奏？

**决策框架构建**：
- 从发现到决策：每个关键发现对产品决策意味着什么，标注影响哪类决策（做不做 / 做什么 / 怎么赢 / 怎么赚 / 怎么避坑）
- 置信度分级：哪些判断可以立即行动，哪些需要先验证
- 风险评估：最可能出错的是什么

### 产出

Phase 3 组装一份完整的研究文档 `research-report.md`，包含三个分层章节：

**第一层：决策简报**（文档顶部，最核心）

最多 2 页。基于 `templates/research-report.md` 的决策简报章节：

- 一句话结论
- 关键决策表（决策 | 推荐方向 | 置信度 | 理由链）
- 机会窗口表
- 风险与待确认表（合并关键风险和待验证问题）
- 需求衔接（为谁解决什么问题 / 产品定位 / 边界和约束 / 怎么算成功 / 下一步行动）

**需求衔接**说明：决策简报解决"做不做"，需求衔接解决"接下来怎么写需求"。从调研结论中提取四个维度的结论，让 PM 决定推进后可以直接开始需求定义，不需要重新翻找研究材料：

| 维度 | 从哪提取 | 写什么 |
|------|---------|--------|
| 为谁解决什么问题 | 用户行为变化 + 竞品痛点空白 | 目标用户 + 核心痛点（1-2 句话） |
| 产品定位 | 深层判断中的差异化机会 + 关键决策的推荐方向 | 价值主张 + 与竞品的核心差异 |
| 边界和约束 | 关键风险 + 路径依赖 + 监管/技术限制 | 必须满足的 + 明确不做的 |
| 怎么算成功 | 机会窗口的潜力评估 + 竞争格局中的基准数据 | 成功指标方向 + 可参考的行业基准 |
| 下一步行动 | 待确认问题中最高优先级的 + 关键决策中需要先验证的 | 2-3 个具体行动项，带时限 |

**第二层：决策推理**（决策简报之后）

每个决策的完整证据链：

- 决策推理（从证据到判断的完整推理过程）
- 行业演变分析（完整演变叙事）
- 竞争态势分析（现状对比分析）
- 深层判断（趋势与现状交叉的新判断）
- 置信度评估
- 未验证假设

**第三层：研究数据**（文档后半部分）

需要深挖或质疑结论时参考的原始研究材料：

- 行业演变（因果叙事 + 关键转折点 + 路径依赖）
- 竞争格局（竞争场景判断 + 方案聚类 + 竞品深度对比）
- 验证发现（高/中置信发现 + 信息矛盾点）
- 开放问题
- 信息源附录（所有来源的编号、名称、类型、可信度、访问时间、URL）

## 交付

Phase 3 组装完完整文档后，询问用户的消费场景：

> 研究完成。你需要什么样的交付？
>
> | 场景 | 你会拿到 | 适合 |
> |------|---------|------|
> | **快速决策** | 决策简报 + 需求衔接（含下一步行动）（1-2 页） | 自己做判断，决定推进后直接开始写需求 |
> | **向上汇报** | 决策简报 + 决策推理 + 风险 | 给老板/上级看，需要"为什么" |
> | **团队讨论** | 完整分析 + 关键数据 | 和团队对齐，需要细节支撑讨论 |
> | **完整存档** | 全部内容 | 留档备查，后续可能深挖 |
>
> 格式：Markdown / HTML 交互报告

用户选择后，从完整文档中提取对应内容，按选定格式输出到 `[输出目录]/`：

- **快速决策**：提取第一层，输出为独立文件或仅展示
- **向上汇报**：提取第一层 + 第二层（不含完整行业演变/竞争态势分析），输出为独立文件或仅展示
- **团队讨论**：提取第一层 + 第二层 + 第三层关键数据（不含开放问题等次要内容），输出为独立文件或仅展示
- **完整存档**：输出完整 `research-report.md` + `research-report.html`

所有场景始终产出 `research-report.md`（三层完整文档）。HTML 版本在用户选择 HTML 格式时生成。

HTML 交互报告使用三层导航（决策简报 / 决策推理 / 研究数据），第一层默认展开，第二/三层通过导航锚点跳转。CSS 样式参照 `cases/` 目录中已有案例的 HTML 产出，关键规范：
- `table-layout: auto` + 内容感知 colgroup 收缩短值列
- `.decision-table` 保留 `table-layout: fixed` + 显式列宽百分比
- `th { white-space: nowrap }`，`td { word-break: break-word }`
- 表格样式以 `cases/` 目录中的已验证 HTML 报告为准，避免依赖外部项目记忆或本地私有文件

**被其他 skill 调用时**：不询问消费场景，直接产出完整 `research-report.md`。调用方自行决定读取哪些章节。

## 产出规范

### 文件结构

```
[输出目录]/
├── research-report.md          ← 完整研究文档（三层结构，始终产出）
└── research-report.html        ← HTML 交付版（用户选择 HTML 格式时产出）
```

### 分层规则

1. **层间不重复**：第一层是决策+推荐+置信度，第二层是推理链，第三层是原始证据。每层添加新信息，不复述上层
2. **散文通过 so-what 测试**：删掉这段后是否影响任何决策推荐？不影响就删
3. **表格承载决策，散文承载推理**：第一层纯表格，第二层先叙事再表格提炼
4. **可信度标注一切**：每个关键发现带 [高/中/待验证] 标签
5. **行内引用可追溯**：引用数据时标注来源编号 `[S编号]`，读者可通过编号在信息源附录中找到原文 URL

### 信息源附录

Layer 3 末尾附"信息源"章节，格式如下：

| # | 来源 | 类型 | 可信度 | 访问时间 | URL |
|---|------|------|--------|---------|-----|
| S1 | 来源名称 | 原始来源/权威分析/二手分析/观点评论 | 高/中 | YYYY-MM-DD | https://... |

- **编号**：S1, S2, S3, ...，按首次出现顺序递增
- **类型**：与可信度框架一致（原始来源/权威分析/二手分析/观点评论）
- **URL**：必须填写，搜不到原文的标注"待补充"
- **访问时间**：标注访问日期，过时信息可在可信度评估时自动降级

### 可信度标注系统

引用 `references/confidence-framework.md`：

| 标签 | 含义 | 使用条件 |
|------|------|---------|
| [高] | 多源一致确认，来源可信 | 3+ 独立来源，含至少 1 个原始来源 |
| [中] | 单源但权威，或 2 个来源部分一致 | 权威方文档/报告，或 2 个独立来源 |
| [待验证] | 逻辑推断但缺乏直接证据 | 基于模式推断，需用户研究或实验验证 |

**注意**：置信度分布由证据实际强度决定，不预设数量配额。不同研究主题的证据密度差异很大——可能产生"8高/3中/6待验证"或"4高/9中/4待验证"等不均匀分布，这是正常的。

## 约束

1. **决策导向**：所有产出的价值标准是"是否帮助了产品决策"，不是"收集了多少信息"
2. **信息质量 > 数量**：精读 5 篇高质量 > 泛读 20 篇低质量
3. **标注不确定性**：明确区分"已验证事实"和"待验证假设"，绝不编造
4. **避免过度推断**：从信息到洞察要有逻辑链条，推测标注"待验证"
5. **主题无关性**：不预设研究领域，完全由输入决定
6. **可追溯性**：每个关键数据点必须可追溯到信息源附录中的具体条目，正文中以 `[S编号]` 标注
7. **产出规模控制**：完整研究文档建议 8000-15000 字（中范围主题）。超过 15000 字时执行 so-what 测试：对每个发现问"这改变了什么决策？"，不影响决策的发现降级为 Layer 3 脚注或删除。Layer 1 决策简报严格控制在 2 页以内
8. **长研究会话管理**：如果 Phase 1+2 累积信息过多，在 Phase 3 组装前先执行 so-what 测试：对每个发现问"这改变了什么决策？"，不影响决策的发现降级为 Layer 3 脚注或删除
