# 开源仓库文件管理指南

> 从实际踩坑中提炼的原则。每次上传前对照检查。

## 核心原则：仓库是产品，不是实验室

开源仓库展示的是"这个 skill 能产出什么"，不是"我们怎么做到的"。用户通过仓库内容判断 skill 的质量和能力边界——过程性产物会稀释这个判断。

## 文件分类与处置规则

### 必须入库（产品交付物）

| 类型 | 示例 | 位置 |
|------|------|------|
| Skill 核心文件 | SKILL.md、模板、参考文档 | `skill/` |
| 最终版案例 | research-report-v2.md、research-report-v2.html | `skill/cases/` |
| 项目说明 | README.md、CLAUDE.md | 项目根目录 |
| 迭代记录 | creation-log.md、round-N.md | `iterations/` |

### 禁止入库（过程性副产物）

| 类型 | 为什么不该入库 | 正确处置 |
|------|--------------|---------|
| 被否决的设计方案 | 不代表最终能力，误导用户 | 留在本地或删除 |
| 版本对比产物（v1 vs v2） | 用户只需要最好的版本 | 只保留最终版 |
| 设计探索原型 | 布局对比、标签风格对比等是决策过程 | 留在本地或删除 |
| 截图/调试图片 | 浏览器截图、响应式测试截图 | 留在本地或删除 |
| 工作目录中的中间产出 | 与 skill/ 产出重复 | 不入库 |
| 旧方法论案例 | 方法论已迭代，旧案例不代表当前能力 | 删除或归档到 iterations/ |

### 视情况入库

| 类型 | 判断标准 | 处置 |
|------|---------|------|
| 多版本案例 | 两个版本方法论不同且有教学价值 | 保留最终版 + 在 iterations/ 记录差异说明 |
| 设计规范文档 | 是否被 skill 引用 | 被引用则入 skill/references/，否则不入 |
| 测试/验证产出 | 是否有长期参考价值 | 有价值入 iterations/，否则不入 |

## 检查清单：每次 commit 前过一遍

1. **新增文件必要性**：这个文件对用户理解/使用 skill 有直接帮助吗？没有则不入库
2. **案例版本唯一性**：每个案例只保留一个版本（最新的），v1/v2 对比不入库
3. **README 一致性**：删除文件后，README 中的引用是否同步清理？
4. **目录结构清晰性**：用户看到的目录结构是否一目了然？`cases/` 和 `skill/cases/` 不应重复
5. **过程 vs 产物**：这是"我们怎么做到的"还是"skill 能产出什么"？前者归 iterations/ 或不入库

## 这次清理的教训（2026-05-16）

### 发生了什么

Round 3 验证完成后，commit 中包含了大量设计过程产物：
- 3 个布局原型（layout-a-dashboard / layout-c-tabs / tag-styles-comparison）
- v1 和 v2 报告同时存在
- 3 个旧方法论案例（碰一下小助理 / 线下商户私域运营 / 订阅支付流失挽回 v1）
- 工作目录 cases/ 与 skill/cases/ 重复

### 为什么是问题

1. **用户困惑**：看到多个版本和布局原型，不知道哪个是"正确答案"
2. **能力误判**：旧方法论案例不代表当前 skill 水平，但用户无法区分
3. **仓库膨胀**：设计探索产物（截图、对比页、原型）与 skill 功能无关
4. **维护负担**：多版本并存，更新时容易遗漏

### 最终处置

- 只保留 `skill/cases/订阅支付流失挽回/` 下的 v2 报告（md + html）
- 旧案例、v1 报告、设计原型全部删除
- README.md 只保留最终版案例条目

### 沉淀的规则

**"即使我们要给一些好的 case，那也一定是好的 case"**——每个入库的案例都必须代表 skill 当前的最佳能力水平。过程性产物、对比产物、旧版案例全部不入库。

## 副产物管理策略

开发过程中会产生大量副产物（设计原型、截图、v1/v2 对比、调试输出），需要一个策略避免它们污染仓库：

### 本地暂存

```
pd-deep-research/
├── _working/              ← 不入库，gitignore
│   ├── prototypes/        ← 设计原型、布局探索
│   ├── screenshots/       ← 浏览器截图、测试截图
│   └── comparisons/       ← 版本/方案对比页
├── skill/                 ← 入库：skill 交付物
├── iterations/            ← 入库：迭代记录（文字，非产物）
└── CLAUDE.md
```

### .gitignore 建议

```gitignore
# 开发过程副产物
_working/
*.png
*.jpg
*.jpeg
!skill/cases/**/*.png   # 如果案例需要图片则放行
```

### 提交前自问

> "一个新用户 clone 这个仓库后，看到的每个文件都能帮助他理解或使用这个 skill 吗？"

如果答案是否定的，这个文件就不该出现在仓库里。
