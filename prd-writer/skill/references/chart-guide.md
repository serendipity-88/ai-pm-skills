# 图表生成规范

> **权威来源说明**：图表工具的选择由 SKILL.md 衍生规则表决定（Mermaid/PlantUML）。本文件提供各工具的用法细节和进阶选项。修改默认工具时只需改 SKILL.md 衍生规则表，不需要同步本文件。

## UML 图类型、用途与推荐工具

| 图表类型 | 用途 | 适用场景 | 默认工具 |
|---------|------|---------|---------|
| **产品架构图** | 展示系统的层次结构和组件间的静态依赖关系 | 系统设计、组件边界划分、上下游依赖 | Mermaid graph TB |
| **业务流程图** | 展示业务从触发到完成的完整步骤和各角色分工 | 业务流程、用户旅程、多角色协作 | PlantUML sequenceDiagram（泳道时序图） |
| **流程图** | 展示简单的步骤顺序和分支逻辑 | 单一业务流程、决策流程 | Mermaid flowchart |
| **时序图** | 展示对象之间的交互顺序和时间顺序 | 多端交互、接口调用、消息流转 | PlantUML sequenceDiagram |
| **状态机图** | 展示对象的状态转换和流转规则 | 多状态切换、状态流转逻辑 | PlantUML stateDiagram |
| **活动图** | 展示复杂业务流程，支持并行和分支 | 复杂业务流程、并行处理 | Mermaid 或 PlantUML |
| **用例图** | 展示用户与系统的交互、用户目标 | 需求分析、用户场景 | PlantUML usecase |
| **类图** | 展示类的结构、属性、方法、继承关系 | 面向对象设计、接口定义 | PlantUML classDiagram |
| **组件图** | 展示系统组件及其依赖关系 | 微服务架构、模块设计 | Mermaid 或 PlantUML |
| **ER 图** | 展示实体及其关系 | 数据库设计 | PlantUML 或专用 ERD 工具 |
| **部署图** | 展示系统部署结构、节点关系 | 基础设施规划 | PlantUML 或 Graphviz DOT |

## 工具选择原则

| 工具 | 特点 | 语雀兼容 | 适用场景 |
|------|------|---------|---------|
| **Mermaid** | 语法简单、语雀原生渲染、可编辑 | ✅ 原生支持 | 流程图、架构图、活动图（默认首选） |
| **PlantUML** | 语法强大、支持复杂图表、语雀原生渲染 | ✅ 原生支持 | 时序图、状态机、类图、用例图（默认首选） |
| **Fireworks Tech Graph** | 语义化形状、4 色箭头语义、7 种风格、40+ 产品图标，支持架构图/流程图/时序图/状态机等全部 14 种 UML 图 | ⚠️ 需导出 PNG 上传 | 可选增强：用户要求高保真图表时，可替代任意 Mermaid/PlantUML 图 |
| **Graphviz DOT** | 适合自动布局的节点关系图 | ⚠️ 需转 PNG | 网络拓扑、依赖关系 |

> **为什么 Mermaid/PlantUML 是默认？** PRD 是需要反复编辑的活文档。Mermaid/PlantUML 在语雀中原生渲染、任何人可直接编辑。Fireworks 需要 SVG→PNG→上传的额外管线，产出的 PNG 无法在语雀内编辑。

## 图表选择决策树

```
需要画什么图？
│
├─ 需要展示"系统有哪些组件、它们之间什么关系"？（架构图）
│   └─ Mermaid graph TB（语雀原生渲染）
│      └─ 节点多导致图不清晰？→ 拆成多张子图（按层/按域），每张仍用 Mermaid
│      └─ 用户明确要求高保真？→ 可选 Fireworks Tech Graph（见"增强路径"章节）
│
├─ 需要展示"事情怎么做、先做什么后做什么"？（流程图）
│   ├─ 简单步骤顺序 → Mermaid flowchart
│   └─ 多角色协作 → PlantUML sequenceDiagram（泳道时序图）
│
├─ 需要展示"对象之间按什么顺序交互"？
│   └─ PlantUML sequenceDiagram
│
├─ 需要展示"状态如何流转"？
│   └─ PlantUML stateDiagram
│
├─ 需要展示"实体之间什么关系"？
│   └─ ER 图 → PlantUML
│
└─ 图太复杂，单张放不下？
    └─ 拆成多张子图（按层/按域/总分结构），每张独立渲染
```

|---------|---------|---------|---------|

## 关键区分

**产品架构图 vs 业务流程图**：
- 产品架构图：回答"系统由哪些部分组成？"（静态结构）
- 业务流程图：回答"业务是怎么运转的？"（动态过程）

**时序图 vs 流程图**：
- 时序图：强调"谁先调用谁、消息顺序是什么"（角色视角）
- 流程图：强调"步骤1→步骤2→步骤3"（步骤视角）

**状态机图 vs 流程图**：
- 状态机图：强调"在什么条件下、从A状态变成B状态"（状态视角）
- 流程图：强调"先做什么、后做什么"（步骤视角）

| 错误用法 | 问题 | 正确用法 |
|---------|------|---------|
| 用流程图展示多端交互 | 无法表达角色分工和消息顺序 | 用时序图或业务流程图 |
| 用架构图展示业务步骤 | 组件罗列而非流程 | 用业务流程图 |
| 简单步骤用状态机图 | 过度设计 | 用流程图即可 |
| 多角色协作用线性流程图 | 看不到每个角色做什么 | 用泳道流程图或时序图 |

## 复杂图拆分规则

当单张图节点过多导致不清晰时，按以下策略拆分：

| 拆分策略 | 适用场景 | 示例 |
|---------|---------|------|
| 按层拆分 | 分层架构 | 前端层一张、服务层一张、数据层一张 |
| 按域拆分 | 微服务/多业务域 | 支付域一张、订单域一张、用户域一张 |
| 总分结构 | 需要全景 + 细节 | 一张全景概览图（每个域一个节点）+ 每个域一张详细图 |

拆分后每张图独立成段，用标题标注关系：
```
### 2.1 系统架构概览
### 2.1.1 支付域架构
### 2.1.2 订单域架构
```

```
### 2.1 产品架构图

展示系统各组件的层次结构和静态依赖关系。

```mermaid
graph TB
    ...
```
```

**已有图片素材的处理**（Demo 截图、设计稿、数据截图）见 `image-placeholder-rules.md`。只有在素材已存在但当前文档平台 CLI/MCP/API 不支持上传或插入时，才保留占位说明：

```
> 📷 **图片占位**：{类型} - {说明}
```

## PlantUML 时序图写法规范

- 本域/核心系统用颜色标注：`participant "peerpay" as F #orange`，帮助读者快速定位关注的系统
- activate/deactivate 严格标注每个调用的生命周期线，明确每个系统的活跃区间
- note 用于补充业务逻辑和关键说明：`note right: 携带场景标，平台uid`、`note left: 跳过记账`
- 消息文本带步骤编号：`A-> B: 1.下单`、`F-> E: 12.返回团长付可用`，方便评审时按编号讨论
- 系统内部处理用自调用：`F-> F: 16.识别平台团长付场景，指定余额资产`，表达不涉及外部交互的内部逻辑

## 增强路径：Fireworks Tech Graph

> **何时使用**：当用户明确要求高保真图表，或需要对外演示级别的视觉质量时。Fireworks 支持全部 14 种 UML 图（架构图、流程图、时序图、状态机、ER 图、用例图等），不限于架构图。注意：Fireworks 产出 SVG→PNG，无法在语雀内直接编辑，需要额外的导出上传流程。

### 适用场景

| 场景 | 为什么用 Fireworks |
|------|------------------|
| 对外演示材料 | 语义化形状 + 品牌色，视觉信息密度高 |
| AI/Agent 架构（RAG、多 Agent、Tool Call） | 专项语义形状 + 内置 Agent 模板 |
| 技术架构展示（云架构、微服务） | 40+ 产品图标 + 4 色箭头语义 |
| 需要高保真流程图/时序图/状态机 | 比 Mermaid/PlantUML 的文本渲染更清晰美观 |

### 拆图规则

**单张图节点上限 12 个。** 超过时按层/按域/总分结构拆分（同上文拆分规则）。

### 布局约束（生成 SVG 时强制执行）

1. **同层节点不超过 4 个**，超过则换行或拆图
2. **跨层连线必须用正交路由**（L 型折线），禁止对角线穿越组件
3. **8px 网格对齐**：所有坐标 snap 到 8 的倍数
4. **组件间距 ≥ 80px**，箭头路径距组件边缘 ≥ 60px
5. **多条箭头进入同一节点时，错开 Y 坐标 15-20px**，避免重叠
6. **箭头标签必须有白底背景矩形**，防止文字与连线混淆

### 风格选择

PRD 文档配图默认使用 **Style 1: Flat Icon**（白底、清爽、适合打印和语雀）。

| 风格 | 适用场景 |
|------|---------|
| Flat Icon（默认） | PRD 配图、语雀文档 |
| Dark Terminal | 面向开发者的技术文档 |
| Blueprint | 基础设施/部署架构 |
| Notion Clean | 轻量产品文档 |
