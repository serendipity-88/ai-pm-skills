# Round 1: 融合 deep-research + 横纵分析法 → pd-deep-research

**日期**: 2026-05-03
**类型**: 重大重构

## 改动

将 deep-research（四阶段流水线）和 hv-analysis（横纵分析法）融合为 pd-deep-research（三阶段决策导向研究）。

### 核心设计变化

1. **阶段命名从方法论转向决策需求**：
   - 旧：锚点发现 → 深度阅读 → 交叉验证 → 框架整合
   - 新：外面怎么样？→ 到底怎么回事？→ 所以呢？我们该怎么做？

2. **方法论退为内部实现**：
   - 纵轴/横轴/交汇洞察不再作为用户可见的阶段名
   - 锚点评估、交叉验证、可信度标注作为内部机制嵌入各阶段
   - 交叉验证不再是独立阶段，而是 Phase 2 的持续过程

3. **产出从 6 文件改为 3 层分层**：
   - Layer 1：决策简报（`competitive-analysis.md`，最多 2 页，信息密度最高）
   - Layer 2：完整分析（`03-decision-brief.md`，15-25 页，决策推理链）
   - Layer 3：支持数据（`01-landscape.md` + `02-deep-analysis.md`，原始研究材料）
   - 层间不重复，每层添加新信息

4. **新增决策简报（takeaway）**：
   - 一句话结论 + 关键决策表 + 机会窗口表 + 关键风险表 + 待验证问题表
   - 这是用户最核心的产出，从 hv-analysis 和 deep-research 的缺失中补上

5. **新增机会识别**：
   - 两者都没有结构化方法从发现到机会
   - Phase 3 系统性缺口分析：纵横交叉白空间 + 用户痛点空白 + 时机窗口

6. **信息密度规则**：
   - so-what 测试：删掉段落后是否影响决策？不影响就删
   - 表格承载决策，散文承载推理
   - 反 AI 味写作规范成文

7. **独立性原则**：
   - SKILL.md 中不引用任何其他 skill
   - 产出文件使用通用格式
   - 调用方适配逻辑在调用方一侧

8. **命名统一**：
   - skill 名从 `deep-research` 改为 `pd-deep-research`
   - 项目目录从 `deep-research` 改为 `pd-deep-research`
   - 产出目录从 `assets/deep-research/` 改为 `assets/pd-deep-research/`

### 从 deep-research 保留

- 锚点评估（改为内部元数据）
- 批次阅读（隐藏批次编号）
- 交叉验证（嵌入 Phase 2 持续执行）
- 可信度分级（增强为两级系统）
- 假设追踪（三阶段全追踪）
- 模板驱动产出

### 从 hv-analysis 保留

- 纵轴/横轴/交汇框架（作为内部分析视角）
- 竞品场景 A/B/C 处理
- 叙事写作 + 反 AI 味 + 敢下判断（成文为 writing-quality-standards.md）

### 新增

- 决策简报（Layer 1）
- 机会识别（Phase 3）
- 信息密度规则 + so-what 测试
- 可信度标注系统（成文为 confidence-framework.md）
- 写作质量标准（成文为 references/writing-quality-standards.md）

### 删除

- 6 文件产出结构 → 3 层分层
- 交叉验证独立阶段 → 嵌入 Phase 2
- 速读总结 → 被 Layer 1 决策简报替代
- PDF 产出链路 → 不需要
- schema.json → 分层产出结构替代
- 碰一下小助理案例 → 标记为 legacy，不作为新方法论标准

## 原因

1. 两个 skill 同领域各有优势：deep-research 信息质量机制完善但产出信息密度低，hv-analysis 双轴框架直觉但缺 takeaway 和可信度校准
2. PM 核心需求不是研究报告而是决策依据——"这些发现对我做什么产品有什么影响"
3. 信息过多时信息密度比信息量更重要——案例显示仅 10-15% 直接可行动
4. 方法论阶段暴露给用户增加认知负担——PM 不需要知道"锚点发现"和"交叉验证"是什么

## 用户反馈

- "深度调研是过程不是产品，不能本末倒置追求形式而忽略要解决的问题"
- "takeaway 是最重要的环节"
- "碰一下小助理案例不应保留——按渐进式披露设计新案例"
- "pd-deep-research 必须独立，内部不引用任何其他 skill"
- "命名统一，不出现旧 skill 名避免调用失败"
