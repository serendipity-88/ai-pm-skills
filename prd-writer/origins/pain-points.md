# 痛点与动机

## 核心痛点

项目开发完成后需要补 PRD，但：

1. **手写 PRD 耗时**：一个中等复杂度的需求，PRD 写作需要 2-4 小时
2. **AI 生成的 PRD 不能用**：直接让 AI 写 PRD，输出充满 AI 套话（"本模块解决的核心问题是..."）、视觉参数（"38px 白色加粗字体"）、空洞修饰（"显著提升"），和真实 PRD 风格差距很大
3. **格式不统一**：不同产品经理写出的 PRD 格式各异，缺乏结构化模板
4. **先做后写的工作流缺失**：大多数 PRD 工具假设 PRD 是开发起点，但实际工作中经常是先做 Demo 再补文档

## 期望

- 基于已有材料（方案文档、代码、设计规范）自动生成 PRD
- 输出风格匹配团队真实的 PRD 写法，不是 AI 味的文档
- 支持交互式确认关键决策（成功指标、约束、受众）
- 框架先行，用户确认后再填充内容

## 素材来源

- 3 类真实 PRD 片段（H5 页面、技术链路、数据实验）
- 内部 PRD 培训课程要点
- NFC支付场景的实际项目经验
