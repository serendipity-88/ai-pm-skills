## 一、需求概述

### 1.1 业务背景与问题定位

支付成功页目前仅展示支付结果，流量未被有效利用。用户在完成支付后页面即结束使命，大量精准的支付场景流量被浪费。

核心问题：支付成功页仅有支付结果展示功能，缺乏流量运营能力。

### 1.2 目标价值

**定量目标**：
- 推荐点击率：5%
- 单页推荐曝光 uv：1000w/天

### 1.3 目标人群

| 角色 | 描述 |
|------|------|
| 用户 | 完成支付的用户 |
| 商家 | 接入推荐能力的商家 |

## 三、产品方案详述

### 3.1 支付金额展示区

位于页面顶部，展示支付结果：

* 展示「支付成功」状态标识
* 展示商家名称
* 展示实付金额（大字突出）
* 展示支付方式

### 3.2 订单详情区

默认展开，展示订单核心信息：

* 展示商品信息（商品名称、数量）
* 展示订单号
* 展示支付时间
* 点击可收起/展开（具体设计以视觉稿为准）

### 3.3 推荐区

位于订单详情下方，营销功能区域。

**默认状态**：收起状态

* 展示标题「为你推荐」
* 展示推荐条数角标（如「3 条优惠」）
* 点击「展开」展开推荐区

**展开状态**：

* 展示推荐卡片列表（1-5 条，可配置）
* 每条推荐卡片包含：图标、标题、副标题、操作按钮
* 底部展示「不感兴趣」入口

**推荐卡片类型**：

1. 商家优惠券
   * 图标：优惠券标识
   * 标题：券名称（如「满30减5元券」）
   * 副标题：适用范围 + 有效期
   * 操作：点击「领券」跳转领券页

2. 附近商家
   * 图标：位置标识
   * 标题：商家名称
   * 副标题：距离 + 评分
   * 操作：点击「查看」跳转商家页

3. 猜你喜欢
   * 图标：推荐标识
   * 标题：推荐内容名称
   * 副标题：推荐说明
   * 操作：点击「看看」跳转详情页

**不感兴趣隐藏**：

* 点击「不感兴趣」隐藏整个推荐区
* 隐藏后本次会话不再展示
* 隐藏状态不上报服务端（具体设计以视觉稿为准）

### 3.4 配置化设计

商家可在运营后台配置：

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| recommendEnabled | boolean | false | 是否开启推荐 |
| recommendTypes | string[] | ['coupon', 'nearby', 'recommend'] | 展示哪些类型 |
| recommendCount | number | 3 | 展示条数（1-5） |

## 五、数据度量

### 5.1 指标分层体系

**核心指标**：
| 指标 | 定义 | 目标值 |
|------|------|--------|
| 推荐点击率 | 点击 uv / 曝光 uv | 5% |

**过程指标**：
| 指标 | 定义 |
|------|------|
| 推荐曝光 pv | - |
| 各类型推荐点击率 | 商家券 / 附近商家 / 猜你喜欢 |

### 5.2 埋点清单

| 事件 | 触发时机 | 关键参数 |
|------|---------|----------|
| recommend_expose | 推荐区展开曝光 | uid, types, count |
| recommend_click | 推荐卡片点击 | uid, type, cardId |
| recommend_hide | 点击不感兴趣隐藏 | uid |

## 六、风险与应对

| 视角 | 风险 | 应对 |
|------|------|------|
| 用户 | 推荐内容打扰用户体验 | 提供「不感兴趣」隐藏入口，默认收起减少干扰 |
| 商家 | 推荐内容影响商家转化 | 商家可配置推荐开关和展示类型 |
| 平台 | 推荐曝光量大，接口压力大 | 优先展示缓存数据，降级兜底 |
| 监管 | 推荐内容合规性 | 仅展示优惠券、附近商家等常规营销内容 |
